Purpose

Why this brief exists

NativeWorks has selected Canela by Commercial Type as the display typeface for the NativeWorks brand. The typeface is locked into the brand identity and is in active use in all delivered brand files. A licence must be procured before nativeworks.studio goes live.

This brief sets out what we know, what we need, and what requires the designer's confirmation before any purchase is made. The designer consultation should resolve every open question so that the licence purchase is made correctly the first time.

What we know

The typeface and its current usage

The typeface

Canela — by Commercial Type (commercialtype.com)

Current usage in delivered brand files

Canela is used in the following delivered files, currently served via Georgia/serif fallback for draft purposes:

FileCanela usage
NativeWorks_Brand_Identity_v1.html Display specimens, mark wordmark ("NATIVE" element)
NativeWorks_MainPage_v1.html All hero copy, section headlines, pull quotes
NativeWorks_About_v1.html All display headlines and pull quotes

Locked type scale — Canela usage

RoleSizeWeight
Hero64–72pxRegular
Display40–48pxRegular
Heading28–32pxRegular

The brand identity specifies Regular weight for all display usage. The wordmark uses Canela in the "NATIVE" element. No other weights are currently specified in the locked brand identity.

What Canela is NOT used for

Body copy, UI elements, navigation, captions, and the "WORKS" wordmark element all use DM Sans — which is open source via Google Fonts and requires no licence.

Entity structure

Context for the licence decision

NativeWorks operates through three legal entities. The licence structure must reflect this correctly.

EntityRoleRelevance to licence
NW Entity HK (PRIMARY HOLDCO) IP owner. Brand owner. Domain owner. Likely the correct entity to hold the master licence.
NW Entity UAE (OPERATIONS) Operates platform under licence from HK. Non-EU clients. Uses the brand under HK licence — may need to be covered under the typeface licence.
NW Entity Denmark (EU FIAT) Operates platform under licence from HK. EU clients. Uses the brand under HK licence — may need to be covered under the typeface licence.
Critical question

Can NW Entity HK hold the master Canela licence as the brand IP owner and extend usage rights to NW Entity UAE and NW Entity Denmark as operating entities under the NativeWorks brand? Or does Commercial Type require each operating entity to hold its own licence? This has cost and structural implications and must be confirmed before purchase.

Five questions

What the designer must answer

The following questions must be answered before any licence is purchased. No purchase proceeds until all five are resolved.

Question 01
Which weights are required?
The brand identity currently specifies Canela Regular only. Before purchasing, confirm:
  • Is Regular the only weight needed for the current scope — website, wordmark, landing pages?
  • Is Italic required? (Pull quotes, editorial moments — Canela Italic is a separate weight at Commercial Type)
  • Is Light or Deck required for any application?
  • Are any additional weights anticipated for Phase 6–8 product work — dashboards, onboarding flows, documentation?
Recommendation: purchase only what is needed now. Additional weights can be added later. Over-purchasing at this stage is unnecessary.
Question 02
Which licence types are required?
Commercial Type offers the following licence types. Confirm which apply:

Licence typeLikely needed?Notes
Web / Digital licence Yes — required For nativeworks.studio and all product pages. Based on monthly pageview tiers.
Desktop licence Possibly — confirm For use in design files, documents, presentations. Based on number of users. Who at NativeWorks will set type in desktop applications?
App licence Not currently — confirm No mobile or desktop app in current roadmap. Confirm this is not needed for Phase 6–8 products.
Broadcast / video licence Not currently — confirm No video production in current roadmap. Confirm.
Question 03
What is the correct web licence tier?
The web licence is based on monthly pageview volume. Confirm:
  • What is the appropriate starting pageview tier for nativeworks.studio at launch?
  • Is the licence per domain (nativeworks.studio only) or does it cover subdomains and future product domains?
  • Can the licence be upgraded as traffic grows without purchasing a new licence from scratch?
Question 04 — Critical
How does the licence cover three operating entities?
This is the critical question. Confirm with the designer and if necessary with Commercial Type directly:
  • Can NW Entity HK hold the master licence as brand IP owner and extend usage rights to NW Entity UAE and NW Entity Denmark as operating entities under the NativeWorks brand?
  • Or does Commercial Type require each entity operating under the brand to hold its own licence independently?
  • If sub-licensing is not permitted, what is the recommended structure — one licence with multiple named entities, or separate licences per entity?
Question 05
Does the wordmark require special consideration?
The "NATIVE" element of the NativeWorks wordmark is set in Canela. Confirm:
  • Is a standard web and desktop licence sufficient to cover the wordmark as used in SVG and web formats?
  • Is there any additional licence requirement for use of the typeface within a registered or commercially-used wordmark/logo?
Minimum coverage

What the licence must cover at minimum

At minimum, the Canela licence must cover the following before nativeworks.studio goes live:

  • 01
    Web use on nativeworks.studio — all current and planned pages (main, /about, /stack, /foundation, future product pages)
  • 02
    Desktop use for brand, design, and document production across NativeWorks
  • 03
    The wordmark — NATIVE element in all formats in which it is used (web SVG, HTML, documents)
  • 04
    All three NativeWorks entities — or a single entity with confirmed coverage of the others under sub-licence
Consultation agenda

What to bring to the designer consultation

The designer should come prepared to advise on all six of the following. The output of the consultation is a recommendation Neo can approve before any purchase is made.

  • 01
    Recommended weight set for current scope and anticipated Phase 6–8 scope
  • 02
    Recommended licence type combination (web + desktop as minimum)
  • 03
    Recommended web pageview tier for launch
  • 04
    Entity structure recommendation — how to structure the licence across three operating entities
  • 05
    The wordmark question — whether standard licence covers the wordmark use case
  • 06
    Total cost estimate for recommended licence structure
After the consultation

What happens once the designer has answered

  1. Neo reviews and approves the recommended licence structure and cost
  2. NW Entity HK executes the purchase as the IP-holding entity
  3. Licence documentation stored at nativeworks/docs/legal/licences/
